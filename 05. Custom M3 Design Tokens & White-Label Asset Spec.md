# Custom M3 Design Tokens & White-Label Asset Spec

**Proyek:** Redesign & Re-Architecture Master Platform Digibi (White-Label Ecosystem)  
**Target Implementasi:**  
* **Web Dashboard:** Angular CSS Custom Properties (`--dg-*`) + Tailwind CSS / Angular Material  
* **Mobile App:** Android Jetpack Compose (`CompositionLocal` + Custom `MaterialTheme` M3)

---

## 1. Arsitektur 3 Lapis Design Token

Agar satu *master template* Digibi dapat didistribusikan ke puluhan klien dengan identitas visual berbeda tanpa mengubah kode sumber, sistem token dibagi menjadi tiga lapisan:

1. **Layer 1 — Primitive / Core Tokens (Statis):** Skala warna netral (*slate*), skala *spacing* kelipatan `4px / 4dp`, dan hierarki tipografi Material 3. Dikunci oleh sistem master.
2. **Layer 2 — White-Label Semantic Tokens (Dinamis dari Database):** Token warna utama, permukaan, dan kelengkungan sudut yang nilainya di-override oleh JSON `/api/v1/tenant/bootstrap`.
3. **Layer 3 — Domain Component Tokens (Turunan Otomatis):** Token spesifik untuk komponen khas Digibi (kartu saldo ganda, latar ikon SVG, badge status tagihan) yang diturunkan secara otomatis dari Layer 2.

## 3. Aturan Auto-Contrast (WCAG AA Protection)

Karena admin klien dapat memilih warna `brandPrimary` bebas melalui *White-Label Studio*, front-end wajib menghitung tingkat kecerahan (*relative luminance* $L$) sebelum menentukan warna teks `onBrandPrimary`:

$$L = 0.2126 \times R + 0.7152 \times G + 0.0722 \times B$$

* Jika $L > 0.55$ (klien memilih warna terang seperti kuning cerah atau hijau muda), sistem otomatis menetapkan `onBrandPrimary = #0F172A` (gelap).
* Jika $L \le 0.55$ (klien memilih warna gelap seperti maroon, navy, atau hijau tua), sistem menetapkan `onBrandPrimary = #FFFFFF` (putih).

## 4. Spesifikasi Teknis Logo & Ikon Menu Utama (SVG Format)

### 4.1 Kontrak File SVG Klien
1. **Logo Organisasi / Klien:**
   * Wajib tersedia dua varian: `logoLightUrl` (untuk latar terang) dan `logoDarkUrl` (untuk header gelap/warna primer).
   * Rasio aspek fleksibel dengan tinggi kanvas standar `32px` dan *transparent background*.
2. **Ikon Menu Utama (`tenant_menus`):**
   * Wajib berformat `.svg` dengan `viewBox="0 0 24 24"` dan area aman (*safe zone*) `20x20` di tengah.
   * Dilarang menyematkan tag `<image>` (bitmap/PNG di dalam SVG) atau tag `<style>` eksternal agar parser Android Vector/Coil berjalan mulus.
   * **Dua Mode Rendering:**
     * `tinted`: SVG dibuat monokrom (`fill="currentColor"` atau `#000000`) sehingga Angular dan Kotlin otomatis mewarnai path-nya menggunakan token `iconTint` klien.
     * `multicolor`: SVG mempertahankan palet ilustrasi multi-warna khusus yang dirancang untuk klien tersebut.

### 4.2 Arsitektur Rendering di Angular & Kotlin
* **Angular (Standalone Component `<dg-svg-icon>`):** Mengambil file SVG via `HttpClient` dengan *in-memory cache* (`Map<string, SafeHtml>`), menyuntikkan inline `<svg>` melalui `DomSanitizer`, lalu menerapkan `fill: var(--dg-icon-tint)` jika `mode === 'tinted'`.
* **Android Kotlin (Jetpack Compose + Coil 3):** Menggunakan `AsyncImage` dengan decoder `SvgDecoder.Factory()`. Jika `mode === 'tinted'`, terapkan `ColorFilter.tint(DigibiTheme.colors.iconTint)`. Jika unduhan gagal, parameter `error` langsung menampilkan *default vector drawable* lokal.
