# Audit UX/UI & Inventarisasi Data Sistem Existing

**Proyek:** Redesign & Re-Architecture Master Platform Digibi (Dedicated White-Label Factory)  

**Target Migrasi:**  
* **Web Dashboard:** Angular Legacy $\rightarrow$ Latest Angular (Standalone Components, Signals, Tailwind CSS / Angular Material, CSS Variables)  
* **Mobile App:** Android Java Manual $\rightarrow$ Android Kotlin Native (Jetpack Compose, Custom M3 Design System, Coil 3 SVG, Spring Motion)  

**Peran Penyusun:** System Designer — Aziz Pasha Andlyan

---

## 1. Ringkasan Eksekutif Audit

Platform **PT Digibi Intellecta Teknologi** memiliki cakupan ekosistem bisnis yang kuat (Koperasi Digital, Cashless School/Pesantren, Niaga/Mart, PPOB, ZISWAF, Umrah & Haji, Event, serta Media Online). Namun, antarmuka *existing* masih mewarisi pola desain *legacy* yang kaku dan belum terstruktur untuk kebutuhan distribusi *dedicated white-label* per klien.

### Empat Masalah Fundamental Sistem Existing:
1. **Cognitive Load Tinggi:** Penggunaan blok warna solid yang kontras secara berlebihan (pada Web Dashboard) dan kepadatan elemen tanpa hierarki visual (pada Mobile App).
2. **Pencampuran Peran (Role Leakage):** Menu operasional khusus petugas/kasir (seperti `Admin Blanja&Tunai`) diletakkan sejajar dengan layanan anggota umum di beranda aplikasi.
3. **Inkonsistensi Komponen & Bahasa:** Campuran bahasa Inggris-Indonesia yang kaku pada *placeholder* (`"Enter the required title"`, `"Enter the required product"`), serta penggunaan gaya ikon yang tidak seragam (campuran ilustrasi vektor, ikon datar, dan foto realistis).
4. **Kesiapan White-Label Terbatas:** Belum adanya sistem *Design Token*, *Dynamic Typography*, dan *Dynamic Asset Pipeline* (logo & ikon menu SVG) sehingga kustomisasi tema setiap ada *deal* klien baru membutuhkan modifikasi kode manual.

### 2.2 Inventarisasi Variabel Data Web Dashboard (Database Mapping)

Data berikut wajib dipertahankan dan dipetakan ulang ke kontrak JSON API baru:
* **Metrik Keanggotaan:** `total_anggota_terdaftar`, `total_anggota_aktif`, `pernah_login_count`, `tidak_aktif_count`, `belum_aktivasi_count`.
* **Metrik Pembiayaan (Pinjaman):** `total_pengajuan_pinjaman` (nominal & jumlah anggota), `total_pinjaman_disetujui`, `total_pinjaman_ditolak`.
* **Metrik Likuiditas & Top Up:** `saldo_topup_cash`, `saldo_topup_paylater`, `total_penggunaan_next_period`.
* **Metrik Simpanan Koperasi:** `total_saldo_simpanan`, `total_transaksi_simpanan`, `total_transaksi_penarikan` (masing-masing dirinci menjadi **Simpanan Pokok**, **Simpanan Wajib**, dan **Simpanan Sukarela**).

## 4. Standar Teknis Aset White-Label (Aturan Wajib SVG, Warna, & Tipografi)

Agar satu *master codebase* Angular dan Kotlin dapat memproduksi dan melayani banyak *instance* klien dengan identitas visual berbeda:

1. **Kontrak Ikon Menu Utama (SVG Format):**
   * Kanvas standar wajib `viewBox="0 0 24 24"` dengan *safe area* `20x20`.
   * Mendukung dua atribut rendering dari database:
     * `iconRenderMode: "tinted"` — Menggunakan `currentColor` / hitam solid sehingga front-end mewarnai ikon otomatis sesuai `--dg-icon-tint` klien.
     * `iconRenderMode: "multicolor"` — Mempertahankan ilustrasi multi-warna asli milik klien.
   * Wajib memiliki *local fallback icon* di aplikasi jika URL CDN gagal dimuat.
2. **Custom Material 3 (M3) Design Tokens & Typography:**
   * Geometri bentuk komponen (*border-radius* kartu `16dp`, tombol `12dp`, kontainer ikon `14dp`) dikunci standar oleh *master template* agar tampilan tetap presisi dan konsisten.
   * Klien dapat mengatur konfigurasi warna (`brandPrimary`, `onBrandPrimary`, `brandSecondary`, `surfaceCanvas`, `surfaceCard`, `walletDompetStart`, `walletSimpananAccent`) serta pasangan **Google Fonts** (`headingFamily` dan `bodyFamily`) di tabel `tenant_branding`.
